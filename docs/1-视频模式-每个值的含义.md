# 视频模式 · 源码里每个值代表什么

> 源码：`src/display_oc_vdo.c`。这份文档逐个解释里面的每个数。

---

## 一、机型配置段（换机型只改这一段）

### `PM` —— 面板模块名

```c
#define PM "panel_n11a_42_02_0a_dsc_vdo"
```

**怎么查**：

```
cat /proc/modules | grep panel
```

会列出十几个面板模块，找到属于你这块屏的那个。

**为什么重要**：这十几个模块里**都有同名的 static 函数**（`lcm_get_modes`、`mtk_panel_ext_param_set`）。kprobe 的符号名不带模块前缀，就会挂到别的面板模块上。

症状是**「模块装上了，但一点反应没有」**——这个坑能卡住好几个小时。

```c
// 正确
.kp.symbol_name = PM ":lcm_get_modes"

// 错误，会挂到别的面板上
.kp.symbol_name = "lcm_get_modes"
```

### `PANEL_W` / `PANEL_H` —— 屏幕可见分辨率

```c
#define PANEL_W	1220
#define PANEL_H	2712
```

**怎么查**：

```
cat /sys/class/drm/card0-DSI-1/modes
```

**作用**：档位表里可能混着副屏、低分辨率档位。用这两个数把主屏的档位筛出来。

### `BASE_HZ` —— 原厂最高档

```c
#define BASE_HZ	120
```

所有比例的基准。原厂最高是 120 就填 120。

### `NUM` / `DEN2` —— 链路倍率

```c
#define TOP_HZ	144
#define NUM	144
#define DEN2	120
```

**`NUM / DEN2` 就是链路要抬多少倍。**

爬坡的时候**只改这三个数**，结构一个字不动：

| 想做到 | TOP_HZ | NUM | DEN2 | 链路 1100 变成 |
|---|---|---|---|---|
| 126 | 126 | 126 | 120 | 1156 |
| 130 | 130 | 130 | 120 | 1192 |
| 132 | 132 | 132 | 120 | 1210 |
| 144 | 144 | 144 | 120 | 1320 |

## 二、结构体偏移段

### `EXT_PARAMS = 8`

```c
struct mtk_panel_ext {
    struct mtk_panel_funcs *funcs;      // +0   指针，8字节
    struct mtk_panel_params *params;    // +8   ★ 我们要的
    int is_connected;                   // +16
};
```

拿到 `mtk_panel_ext` 指针后，**加 8 读出来的就是参数结构体的地址**。

### `PP_PLL_CLK = 0` / `PP_DATA_RATE = 4`

```c
struct mtk_panel_params {
    unsigned int pll_clk;     // +0
    unsigned int data_rate;   // +4
    ...
};
```

**这两个值恒等于 `data_rate = pll_clk × 2`。**

这个关系是**自检的关键**——读出来对不上，说明偏移数错了：

```c
if (!(pll && dr && dr == pll * 2 && dr >= 100 && dr <= 8000)) {
    /* 拒绝写 */
    return;
}
```

> 实测 K70e 读到 `pll=550 dr=1100`，550×2=1100 ✓

### `PP_PHY_TIMCON = 8` / `PP_TIMCON_N = 15`

```c
struct mtk_dsi_phy_timcon {   // 15 个 unsigned int，共 60 字节
    hs_trail, hs_prpr, hs_zero, lpx, ta_get, ta_sure, ta_go,
    da_hs_exit, clk_trail, cont_det, da_hs_sync, clk_zero,
    clk_hs_prpr, clk_hs_exit, clk_hs_post
};
```

这是 DSI 的信号时序参数。

**为什么要全部清零**：驱动里是

```c
#define CHK_SWITCH(a, b)  ((a == 0) ? b : a)
```

**填 0 就等于「按新的 data_rate 自动重算」。**

原厂那套值是按 1100 Mbps 配的。你把链路抬到 1320，还用 1100 的信号时序，边沿对不上 → **花屏**。

### `PP_DYNFPS_DATA_RATE = 124` ★ 最容易漏的一个

```c
struct mtk_panel_params {
    pll_clk;          // +0
    data_rate;        // +4
    phy_timcon;       // +8    15个u32 = 60字节
    vfp_low_power;    // +68
    dyn;              // +72   11个u32 = 44字节
    dyn_fps;          // +116
      // .switch_en        +116
      // .vact_timing_fps  +120
      // .data_rate        +124   ★
};
```

**为什么它最重要**：驱动读链路速率是**按优先级**的：

```c
if (dsi->d_rate != 0)                       // 1. 调试节点才设，平时 0
    data_rate = dsi->d_rate;
else if (DYN_MIPI_CHANGE && params->dyn_fps.data_rate)
    data_rate = params->dyn_fps.data_rate;  // 2. ★ 默认走这条！
else if (params->data_rate)
    data_rate = params->data_rate;          // 3.
else if (params->pll_clk)
    data_rate = params->pll_clk * 2;        // 4.
```

而 `mtk_drm_helper.c` 里写着：

```c
{MTK_DRM_OPT_DYN_MIPI_CHANGE, 1, "MTK_DRM_OPT_DYN_MIPI_CHANGE"},
                              ↑ 默认值 1，是开着的
```

**只改 3 和 4，会被 2 整条压死。** 必须把 +124 清零，才轮得到你改的那两个。

## 三、运行时数据结构

### `want_hz[4]` —— 每一格改成多少

```c
static const u32 want_hz[4] = { 120, 90, 60, TOP_HZ };
                                 ↑    ↑   ↑    ↑
                              名次0 名次1 名次2 名次3
```

**名次**是按**原厂刷新率降序**排的：

| 名次 | 原厂 | 改成 |
|---|---|---|
| 0 | 120Hz | 120Hz（不变） |
| 1 | 90Hz | 90Hz（不变） |
| 2 | 60Hz | 60Hz（不变） |
| 3 | 30Hz | **144Hz** ← 把最低那一格换成顶格 |

**为什么这样排**：这样改完之后重新排序，名次还是 0,1,2,3 **一格没动**，驱动按序号取什么都是对的。

> 试过「四档全部重新分配」（120→144、90→130、60→120、30→60），结果**整体减半**——名次乱了，DDIC 收到错档位的帧率命令。

### `par[]` —— 面板参数表

```c
static struct { 
    void *p;                    // 参数结构体地址
    u32 o_pll, o_dr, o_dfps;    // 原值，用来还原
    u32 o_tim[PP_TIMCON_N];     // PHY 时序原值
    bool on;                    // 改过了没
} par[NPAR];
```

面板有四档，**每档一份独立的参数结构体**。链路速率只在上电时编程，而那时 `ext->params` 指着哪一份是不确定的，所以**四份都要打上同一个倍率**。

### `map[]` —— 档位名次表

```c
static struct { void *m; u32 want; u32 hz; } map[NMAP];
```

记录每个档位结构体对应的**原厂名次**。用来验证排序有没有乱。

## 四、关键函数在干什么

| 函数 | 干什么 |
|---|---|
| `psane()` | 指针合法性检查：高 16 位是 0xffff，且 8 字节对齐 |
| `rdk()` | 安全读内存，包了 `copy_from_kernel_nofault` |
| `par_do()` | 给一份面板参数打上倍率（清 +124、改 +4、改 +0、清 phy_timcon） |
| `par_undo()` | 把所有改过的参数还原 |
| `gm_ret()` | 枚举档位时改时序：排名次 → 按 `want_hz` 改 clock 和 vtotal |
| `fpe_ret()` | 钩 `find_panel_ext`，拿到 `mtk_panel_ext` |
| `rate_ret()` | **钩 `mtk_dsi_default_rate`，记录驱动真正采用的链路速率** |
| `irq_pre()` | 数 vsync，算真实帧率 |

### `rate_ret` 为什么最重要

```c
static int rate_ret(struct kretprobe_instance *ri, struct pt_regs *regs)
{
	u32 r = (u32)regs->regs[0];   // x0 = 返回值
	if (r && r != S.last_rate) {
		lgp("*** 驱动采用链路速率 = %u Mbps ***", r);
		S.last_rate = r;
	}
	return 0;
}
```

`mtk_dsi_default_rate()` **只在 `mtk_dsi_poweron()` 里被调用**，所以这行日志是唯一的硬指标：

| 日志表现 | 说明 | 怎么办 |
|---|---|---|
| 这行一直没出现 | DSI 根本没下电上电 | 息屏再亮屏 |
| 出现但还是 **1100** | 被高优先级字段压住了 | 检查 +124 清零了没 |
| 出现且是**新值** | 链路真的生效了 | 看实测帧率 |

## 五、时序怎么算

### 公式

`htotal` 固定时：

```
clock  = 原厂clock × NUM ÷ DEN2        ← 四档共用同一个值
vtotal = NUM × BASE_HZ × 原vtotal ÷ (DEN2 × 目标帧率)
帧率   = clock × 1000 ÷ (htotal × vtotal)
```

**关键认知：四个档位的 clock 完全一样，帧率完全由 vtotal 决定。**

### 代码里对应的地方

```c
clk = div_u64((u64)base * NUM, DEN2);              // 共用的 clock
u16 V = div_u64((u64)NUM * BASE_HZ * 2784, (u64)DEN2 * tgt);  // 每档的 vtotal
```

### vsync 怎么跟着变

```c
m->vsync_start = V - 20;
m->vsync_end   = V - 16;
m->vtotal      = V;
```

**保持 vsa 和 vbp 不变，只拉长 vfp**：

```
原厂 120 档：
  vdisplay     2712
  vsync_start  2764   →  vfp = 2764 - 2712 = 52
  vsync_end    2768   →  vsa = 2768 - 2764 = 4
  vtotal       2784   →  vbp = 2784 - 2768 = 16

所以  vsync_end   = vtotal - 16
      vsync_start = vtotal - 20
```

### 上限在哪

`vtotal` 不能小于 `vdisplay` 加上必要的同步行数。

K70e 的 120 档只剩 **72 行**消隐（2784 - 2712）。

**所以压 vtotal 这条路完全走不通** —— 126Hz 就需要 vtotal = 2651 < 2712，物理不可能。只能抬链路。
