# 红米K60e · 侧载 ko 改刷新率

**22122RK93C ｜ rembrandt ｜ 联发科 ｜ 命令模式屏 ｜ 内核 5.10.198**

> 先看《通用篇》。这台是**最好的参考样本** —— 现成的 ko 能反汇编出来直接学。

---

## 第一步：确认面板模式

```
cat /proc/modules | grep panel
```

找到：

```
panel_m11r_38_0a_0a_dsc_cmd ...
```

**结尾 `_cmd` = 命令模式**，只改主机时序就能超频。

> ⚠️ **同样是联发科，面板模式不同改法完全不同。** 别看到「都是联发科」就照搬到 K70e 上 —— 那台是 `_vdo`。

## 第二步：怎么分析一个现成的 ko

想知道别人的 ko 到底改了什么，**直接拆开看**。

### 看依赖和函数

```sh
# 依赖哪些内核符号
llvm-nm -u k60e_oc.ko

# 自己有哪些函数
llvm-nm k60e_oc.ko | grep ' [tT] '

# 模块参数
strings -a k60e_oc.ko | grep '^parm='
```

### 看它往哪里写

**这一步最关键** —— 把写指令全列出来：

```sh
llvm-objdump -d --disassemble-symbols=target_set k60e_oc.ko | grep -E "\sstr|\sstur"
```

K60e 拆出来是这样：

```asm
target_set:
  str  w8, [x10, #0x4]    ← params + 4  = data_rate
  str  w8, [x9]           ← params + 0  = pll_clk

repatch:
  stur w0, [x12, #-0x40]  ← mode->clock  就地改

undo:
  str  x9, [x8, #0x8]     ← ext->params 指回原厂
  stur w11, [x12, #-0x40] ← mode->clock 还原
```

**结论：它只写两个字段** —— `pll_clk`(+0) 和 `data_rate`(+4)，外加 `mode->clock`。

它**不碰** `dyn_fps.data_rate`，**不清** `phy_timcon`。因为命令模式不靠这些吃饭。

### 从反汇编里读出结构体偏移

```asm
str x10, [x8, #0x8]     → mtk_panel_ext 的 params 在 +8
ldur w9, [x11, #-0x40]  → drm_display_mode 的 head 在 +0x40
ldurh w11, [x9, #-0x3c] → hdisplay 在 +4
ldurh w11, [x9, #-0x36] → htotal 在 +10
ldurh w11, [x9, #-0x2c] → vtotal 在 +20
```

> 这几个偏移在 K70e（6.1 内核）上**完全一样**，可以直接复用。

## 第三步：ko 要钩住的符号

| 符号 | 在哪个模块 | 作用 |
|---|---|---|
| `lcm_get_modes` | 面板模块 | 枚举档位，在这里改 clock |
| `mtk_panel_ext_param_set` | 面板模块 | 切档位时选参数 |
| `find_panel_ext` | `mediatek_drm_panel_drv` | 拿到面板参数结构体 |

### ⚠️ 面板模块里的符号必须带前缀

```c
.kp.symbol_name = "panel_m11r_38_0a_0a_dsc_cmd:lcm_get_modes"
```

不带前缀会挂到别的面板模块上。详见《通用篇》第七步。

### 一个关键细节：第三个参数是序号

`mtk_panel_ext_param_set` 的**第三个参数是档位序号（一个整数）**，不是结构体指针。

```c
int ext_param_set(struct drm_panel *panel,
                  struct drm_connector *connector,
                  unsigned int mode);     // ← 这是序号
```

按指针去解会一直解不出来。正确做法是拿这个序号去 `connector->modes` 链表里数第几个。

### ★ 新增档位之后，不要再信任序号

一新增档位，`drm_mode_sort` 按刷新率重排，**原有每一档的序号都会挪位**。

**解法：序号只用来定位，判断依据用 `mode->clock`。**

K60e 那个 ko 的反汇编里能直接看到这个做法：

```asm
ldr  w9, [x1, #0x10]      ; 拿到序号
ldr  x11, [x10, #0x98]!   ; 按序号走到 connector->modes 的那一项
ldur w9, [x11, #-0x40]    ; 读出这一档的 clock
cmp  w11, w9              ; ★ 拿 clock 去比，不是拿序号去比
str  x10, [x8, #0x8]      ; 命中就把 ext->params 指过去
```

**只要判断依据是 clock，排序怎么变都不影响。** 所以命令模式下新增档位是可行的。

> 视频模式下这招不够用（时序本身依赖每档的参数和 DDIC 状态），那边建议不加档位，见 `docs/1`。

## 第四步：算数值

### 读原厂数据

```
cat /sys/class/drm/card0-DSI-1/modes
dmesg | grep -i dsi | grep -iE "clock|htotal|vtotal"
```

### 公式

```
帧率 = clock × 1000 ÷ (htotal × vtotal)
```

### 两条路

**路一：抬 clock（命令模式下最直接）**

```
新 clock = 原 clock × 目标帧率 ÷ 原帧率
```

**路二：压 vtotal**

```
新 vtotal = 原 vtotal × 原帧率 ÷ 目标帧率
```

⚠️ 先算余量：

```
消隐余量 = vtotal - vdisplay
```

余量只剩几十行就压不动，只能走路一。

### 链路速率要不要跟着抬

命令模式下**可以不抬**。K60e 那个 ko 的 `linkoc` 参数默认可以关，说明**真正干活的是时序**。

抬的话按同样比例：

```
新 data_rate = 原 data_rate × 倍率
新 pll_clk   = 新 data_rate ÷ 2      ← 必须守住
```

### 自检

读出来必须满足 `data_rate == pll_clk × 2`。**对不上就是偏移错了，宁可不改也别乱写。**

## 第六步：出问题怎么办

### 模块装上了一点反应没有

**最常见是符号名没带模块前缀**，钩子根本没挂上。

把 `register_kprobe` 的返回值打到 dmesg，`0` 才是成功。

### 换新版本还是旧行为

```sh
rmmod k60e_oc
insmod 新的.ko
```

内核不允许同名模块装两次。

### 切档位卡在某一档

驱动是按**序号**取时序的。确认序号和你以为的档位对得上。

### 花屏

生效了但过头了，往回退一档。

## 第七步：哪些经验能搬到别的机器

### 能搬

| 经验 | 说明 |
|---|---|
| 结构体偏移 | `ext->params` +8；mode 的 clock/htotal/vtotal 偏移 |
| `ext_param_set` 第三个参数是**序号** | 联发科机型通用 |
| 克隆放模块 `.bss` | 不 kmalloc 交给驱动 free |
| 读内存用 `copy_from_kernel_nofault` | 偏移错了不崩内核 |
| 卸载时把 `ext->params` 指回原厂 | 否则悬空指针，下次切档必崩 |

### ❌ 不能搬（血的教训）

| 做法 | 为什么搬不了 |
|---|---|
| 只改时序就超频 | **只对命令模式成立** |
| `linkoc` 可以关 | 视频模式下链路是唯一的杆子 |
| 新增档位 | 要看驱动是不是按序号取时序 |

> 照搬 K60e 的写法到 K70e 上，花了一整晚才发现：**K60e 拉的那根杆子，在视频模式下根本不存在。**
