# 一加15 · 侧载 ko 改刷新率

**高通平台**

> ⚠️ **这份里没有一加15 的具体数值**（面板代号、原厂时序、符号名）。那些必须从你这台机器上读出来。
> 下面是**完整的取数流程**，跑一遍就能把数据摸出来。先看《通用篇》解决「ko 能不能插进去」。

---

## 第一步：确认面板模式

**这一步决定后面所有写法。**

```
ls /sys/firmware/devicetree/base/soc/ | grep mdss
```

拿到实际节点名后：

```
ls /sys/firmware/devicetree/base/soc/qcom,mdss_mdp@<地址>/ | grep panel
```

会看到类似 `qcom,mdss_dsi_<型号>_dsc_cmd`。

**记下最后三个字母**：

| 结尾 | 意思 | ko 怎么写 |
|---|---|---|
| `_cmd` | 命令模式 | 改 `mode->clock` 就行（照 K70 那份） |
| `_vdo` | 视频模式 | 必须抬链路速率（照 K70e 那份） |

高通旗舰主屏大多是 `_cmd`，但**一定要自己看一眼**。

---

## 第二步：读出原厂时序

```
cat /sys/class/drm/card0-DSI-1/modes
```

> `card0-DSI-1` 不存在就先 `ls /sys/class/drm/` 看实际叫什么。

```
dmesg | grep -i dsi | grep -iE "clock|htotal|vtotal|mode"
```

**要记的数**：

| 名称 | 含义 |
|---|---|
| `clock` | 像素时钟（kHz） |
| `hdisplay` / `htotal` | 横向可见 / 总长 |
| `vdisplay` / `vtotal` | 纵向可见 / 总长 |

### 算消隐余量

```
纵向余量 = vtotal - vdisplay
```

**这个数决定你有没有「压时序」这条路**：

- 几百行 → 可以压 vtotal 提帧率
- 只剩几十行 → 压不动，只能抬时钟/链路

### 验证数读对了没

```
帧率 = clock × 1000 ÷ (htotal × vtotal)
```

算出来必须正好等于标称帧率。**对不上就是读错了，回去重读。**

---

## 第三步：找入口符号

高通这边 ko 通常需要一个显示驱动的入口函数地址。

### 怎么找候选符号

```sh
OLD=$(cat /proc/sys/kernel/kptr_restrict)
echo 0 > /proc/sys/kernel/kptr_restrict

# 看看有哪些相关符号
grep -iE "dsi_display|panel|mdss" /proc/kallsyms | grep -iE "get|primary" | head -40

echo "$OLD" > /proc/sys/kernel/kptr_restrict
```

K70 上用的是 `mi_get_primary_dsi_display`（小米系）。一加的命名不一样，要自己在上面的输出里找。

### 地址要运行时传进去

**不能编译进 ko**（KASLR 每次开机地址不同）：

```sh
ADDR=$(awk '$3=="<你找到的符号>" {print $1; exit}' /proc/kallsyms)
insmod 你的.ko disp_fn=0x$ADDR
```

---

## 第四步：算新数值

### 命令模式（`_cmd`）

```
新 clock = 原 clock × 目标帧率 ÷ 原帧率
```

ko 里把档位结构体的 `clock` 字段改掉就行。

### 视频模式（`_vdo`）

**改 clock 没用**，必须抬链路速率。高通这边链路字段通常叫：

```
qcom,mdss-dsi-panel-bitclk-rate
```

对应到内核结构体里的字段要自己定位。

**同时**：抬链路之后，原有档位的 `vtotal` 要**同比例抬**，否则它们的帧率会跟着变快。

详细思路照《K70e》那份第四到第六步走，原理一样，只是高通和联发科字段名不同。

---

## 第五步：结构体偏移（已验证，跨平台通用）

```
drm_display_mode
  +0    → clock      (u32)
  +4    → hdisplay   (u16)
  +10   → htotal     (u16)
  +20   → vtotal     (u16)
  +0x40 → head       (链表节点)
```

> 拿到链表节点指针后**减 0x40 就是结构体起点**。这个布局在 5.10 和 6.1 内核上都验证过。

---

## 第六步：验证

```
grep '^你的模块名 ' /proc/modules
echo detect > /sys/class/drm/card0-DSI-1/status
cat /sys/class/drm/card0-DSI-1/modes
dmesg | tail -40
```

然后**用测帧率的 App 实测**。

> ⚠️ 系统显示 144 实际跑 120 是最常见的假象 —— 说明只改了标签没改硬件。

---

## 第七步：出问题怎么办

### insmod 失败

见《通用篇》第二、三步（vermagic / CRC / 签名）。

### insmod 成功但没反应

1. 入口符号地址传对了吗（是不是全 0）
2. ko 内部钩子注册成功了吗（把返回值打到 dmesg）
3. 面板是 `_vdo` 而你用了 `_cmd` 的改法

### 换新 ko 还是旧行为

```sh
rmmod 模块名
insmod 新的.ko ...
```

内核不允许同名模块装两次。

### 花屏

**生效了但过头了**，往回退一档。

### 刷新率卡死

```
settings delete system min_refresh_rate
settings delete system peak_refresh_rate
```

---

## 第八步：爬到哪里停

**花屏 = 到顶。**

```
原帧率 → +5% → +10% → +15% → ...
```

每次只改一个数。**别人说最高多少不算数**，自己实测出来的才是你的上限。

---

## 动手前检查清单

- [ ] 面板代号查清楚，结尾 `_cmd` 还是 `_vdo`
- [ ] 原厂 clock / htotal / vtotal 读出来了
- [ ] 用公式验算过，和标称帧率对得上
- [ ] 消隐余量算过了
- [ ] 入口符号找到了，地址不是全 0
- [ ] ko 能插进去（《通用篇》第二三步）
- [ ] **ko 没有开机自动加载** ← 这是黑屏时的唯一保险
- [ ] 第一次只加一档小的（+5%）
